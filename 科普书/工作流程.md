## 二、逐章循环（第 N 章）

```
1. 准备  读 01..N 章全文，从大纲里取出第 N 章的"唯一的活"
2. 评审  校准画像的新读者，只读 01..N 章 → 六维打分（v{N}.0 基线）
3. 判断  真问题 vs 品味问题，定下本轮改什么
4. 修改  只改第 N 章正文
5. 评审  换一位新读者 → v{N}.1、v{N}.2……
6. 过关  分数接近 48 就可以推进，不必死卡；推进不等于结案，后面每一轮的评审读者都从第 1 章读起
```

门禁是参考，不是闸机。推进之后仍要回头关注：前文的问题会在后一章的评审里重新冒出来，冒出来就回头看。

---

## 三、硬规则

1. **一次只动一章。** 改第 N 章时发现影响到第 M 章（M>N），只在 `大纲.md` 第 N 章条目下的"对后续章节的影响"里记一笔，轮到第 M 章再处理。
2. **真问题才改。** 真问题＝违反写作规范／理论口径错／逻辑断裂／读者普遍看不懂。品味问题（个别人觉得案例不好、不够有趣）不改。
3. **评审者独立。** 只读正文，禁止读任何工作文档（大纲、写作规范、评审记录、版本目录）。
4. **画像校准。** 读者画像见第六节，不得写成"零科学背景"。
5. **不许给客气分。** 提示词里必须写明"虚高的分数会让作者失去改进的机会"。
6. **每轮换新读者。** 每轮重新派，不复用。
7. **提交由作者做。** 修改者只管改文件、存快照、记版本，不执行 `git commit`。
8. **门禁从宽，推进后回看。** 分数接近 48（大致 ≥42）就可以推进，不必死卡 48；引子章（第一章）可以更宽。推进不等于结案：后面每一轮的评审读者都从第 1 章读起，前文的问题会在那里冒出来。
9. **只改跟主线有关的。** 先想清楚这一章要表达什么。跟主线无关的细节（某个措辞、某个比喻好不好）不投入精力：要么不管，要么直接删掉，不去打磨它。

## 四、版本快照

- 动手改之前存一份，改完再存一份，都放在 `科普书/版本/`
- 命名 `{章号}.v{章}.{序号}.md`，如 `01.v1.0.md`、`01.v1.1.md`
- 查改动：`diff 版本/01.v1.0.md 版本/01.v1.1.md`
- 只有 14 章正文需要快照；大纲、写作规范、评审记录靠 git 历史
- **分数掉了：先 diff，再决定。** 把历史最高分那一版的快照和当前版逐行对比，把被删、被改的每一处过一遍，逐条判该不该留：
  - **真是回退**（读者点名的好段落被删了）→ 恢复
  - **读者方差**（内容没变或只有改进，分数却掉了）→ 不回退，继续
  - **规范修复**（禁用语、事实错误）→ 不回退，即使它让分数略降
  - 确实要回退时，把最高分那版拷回正文，在它基础上重改；三类判定都记进评审记录
- 教训：第二章 v2.4 拿 46，后来叠出 37，diff 一看只是加了三处改进、一字未删，那是方差；第四章 v4.0 拿 40，重写后掉到 32，diff 后确认删掉的大多是读者要求删的，但另有两处真问题未解决。**先 diff 比继续叠改或无脑回退都可靠。**

## 六、读者评审：画像与提示词

### 读者画像

目标读者是《人类简史》《反脆弱》《思考，快与慢》那一档的读者：

- **已经有**：基础科学概念（熵、热力学第二定律、进化论、随机性、概率），不需要从头解释这些词
- **还没有**：本理论这一套，没读过相关理论书，也不预设它成立
- **在意的**：论证严不严、案例可信不可信、有没有被灌鸡汤或被当成不懂科学的人哄

> 旧的提示词写的是“你的知识必须和书店里的普通读者一样少”（零科学背景），过严：会系统性压低完成度／可信度，还会把作者正常使用科学常识误报成术语漂移。2026-09-11 修正。

### 必须交代的背景（否则分数不可用）

读者只能看到前 N 章，看不到后文。他天然会把“这一章在铺垫”当成“这一章没东西”，把每个待展开的概念当成没定义。**这类扣分是伪问题**，要在提示词里预先消掉。

提示词里加一段（按实际进度调整章数）：

> 这本书共 14 章。第 1 到 4 章建立概念工具，第 5 章开始用真事检验，第 12 章给诊断工具，最后两章讲为什么系统自己治不好自己、出路在哪。你读到第 N 章为止，这一段的任务就是把地基钉下来。
>
> 评分时请把“这一章在它这个位置上该做完的事有没有做完”算进去：
> - 不要因为“后面还没看到案例”扣分
> - 但如果铺垫本身写得让人读不下去，或者一个概念在这里就含混到影响理解，要直接说

```
## 重要限制
- 只能读这些文件
- 禁止读任何工作文档（大纲.md、写作规范.md、评审记录.md、版本/ 目录等）

## 评价要求

### 一、六维打分（各 1-10 分）
- 完成度：这章是否完整？有没有说到一半就断了？
- 可读性：句子通不通顺？段落节奏如何？
- 可信度：案例和论证能不能说服你？
- 记忆度：合上书你能记住什么？
- 实用性：对你的生活或工作有帮助吗？
- 独特性：有没有给你别的书没给过的东西？

### 二、详细问题清单
- 所有你"读了但说不清"的词或句子，越具体越好
- 所有你觉得"同一个意思说了两遍以上"的地方
- 你差点弃读的位置

### 三、最影响体验的三个问题（按严重程度排序）

### 四、读完这一章，你带走的问题是什么？（用你自己的话，一句）

### 五、还想继续读下一章吗？为什么？

直接给结论，不要复述原文。
```

## 评审提示词必须交代的三件事（2026-09-11 补）

前几轮吃过的亏，全部来自提示词没交代清楚：

1. **案例的规范**（照 `写作规范.md`）：例子的任务是让读者对着一个具体现象想问题，不是提交史料；**不必为史学细节、日期、机构沿革纠缠**。合成场景交代一句就够。提示词里要写明这一条，否则新读者会把预算全花在考据上，用它拉低可信度分——那不是在评这本书自己立的标准。
2. **不能把"没读到后文"当成扣分理由**。要交代全书结构（第 1–4 章建工具、第 5 章起检验、第 7 章讲引擎、第 8 章兑现引擎的燃料、第 12–13 章还两笔账）。
3. **打分要按这本书自己的标准**：反脆弱性"高"没有阈值、只能比较出哪些情况不够好，这是作者公开的口径，不是躲闪。

## 版本快照的两条纪律（2026-09-11 补）

1. **动笔前先存旧版，改完再存新版。**一次改动产生两个快照，缺一个都不算完整。第八章初版就是因为只存了改后版而差点丢失，后来从 git 里取回（`版本/08.v8.0.md`）。
2. **命名一律 `{章号}.v{章}.{序号}.md`**，序号只增不跳、不换"代"（不存在 `01.v2.x` 这种写法）。
