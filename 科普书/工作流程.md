# 工作流程

本文档记录科普书修订的完整工作流程，供后续协作参考。

---

## 一、修订规范 v1.0

### 1. 三阶段流程

```
第一阶段：全书诊断（已完成 2026-09-11）
    ↓
第二阶段：分析与术语统一
    ↓
第三阶段：逐章循环精修
```

### 2. 第一阶段：全书诊断

**目标**：找出现存问题的全貌，为后续修订提供基线。

**操作**：
1. 派 3-4 位独立读者（subagent），每人只读 3-4 章
2. 每位读者：先给全书式评价，再逐章打分
3. 六维打分：完成度/可读性/可信度/记忆度/实用性/独特性，各 10 分
4. 重点收集：读了但说不清的术语、差点弃书的地方、怀疑作者自说自话的地方

**产出**：`评审记录.md` 新增"全书诊断"一节

### 3. 第二阶段：分析与术语统一

**目标**：区分"真问题"与"品味问题"，统一核心术语定义。

**操作**：
1. 逐条分析读者反馈，判断标准：
   - **真问题**：违反写作规范、理论口径错误、逻辑断裂、读者普遍反映看不懂
   - **品味问题**：个别人觉得"不够有趣""案例不喜欢"
2. 在 `写作规范.md` 中统一定义核心术语，确保首次出现时给出锚点
3. 修订大纲使其成为真正的工作指南

### 4. 第三阶段：逐章循环精修

**流程**（以第 N 章为例）：

```
┌─────────────────────────────────────────────────────────┐
│ 1. 精修前准备                                             │
│    - 派代理通读 01..0(N-1) 章                             │
│    - 派代理通读第N章                                       │
│    - 根据大纲确定本章"唯一的活"                             │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 2. 读者评审                                               │
│    - 全新读者，只读 01..N 章                               │
│    - 六维打分 + 详细反馈                                   │
│    - 版本号：v{N}.0                                        │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 3. 分析判断                                               │
│    - 区分真问题 vs 品味问题                                │
│    - 确定本轮修改重点                                      │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 4. 执行修改                                               │
│    - 第N章正文修改                                         │
│    - 必要时修订大纲                                        │
│    - 记录修改内容                                          │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 5. 再次评审                                               │
│    - 新读者，只读 01..N 章                                 │
│    - 六维打分                                              │
│    - 版本号：v{N}.1, v{N}.2...                             │
└─────────────────────────────────────────────────────────┘
                          ↓
    ┌─────────────────────────────────────┐
    │ 分数 ≥48？                          │
    │ 是 → 进入第N+1章                    │
    │ 否 → 检查流程，考虑回溯             │
    └─────────────────────────────────────┘
```

## 二、版本管理规则

1. **每次修改必须记录**：
   - 版本号：`v{章}.{序号}`（如 `v1.6` 表示第1章第6次修改）
   - 修改日期
   - 修改摘要（改了什么、为什么改）
   - 六维分数
   - 字数变化

2. **分数下降时的处理**：
   - 停止当前修改
   - 分析下降原因（通常是：加了不该加的、删了不该删的、改了核心逻辑）
   - 回溯到历史最高分版本，在其基础上重新修改
   - 记录"回溯决策"到评审记录

3. **质量基线**：
   - 单章门禁：≥48/60
   - 总分目标：≥48/60
   - 单项红线：不能有<6的维度

## 三、读者评审提示词模板

派 subagent 做读者评审时，使用以下提示词：

```
你是一位全新的读者，第一次阅读这本科普书。

## 你的任务
阅读 [文件列表]。

## 重要限制
- 只能读这些文件
- 禁止读任何工作文档（大纲.md、写作规范.md、评审记录.md 等）
- 你的知识必须和书店里的普通读者一样少

## 评价要求

### 六维打分（各 1-10 分）
- 完成度：这章是否完整？有没有说到一半就断了？
- 可读性：句子通不通顺？段落节奏如何？
- 可信度：案例和论证能不能说服你？
- 记忆度：合上书你能记住什么？
- 实用性：对你的生活或工作有帮助吗？
- 独特性：有没有给你别的书没给过的东西？

### 详细问题清单
列出所有你"读了但说不清"的词或句子，越具体越好。

### 最影响体验的三个问题

### 你还想继续读下去吗？为什么？
```

---

## 四、给修订代理的上下文规则

派 subagent 改某一章或某一段时，提示词里必须包含：
- "先通读你负责范围之前的所有章节（全文）"
- 本章在大纲中的"唯一的活"
- 本章的当前分数和主要问题

---

## 五、质量门：独立读者评审（硬规则）

1. **独立**：评审者只能读书稿本身，禁止读任何工作文档
2. **双角色**：先当读者（记录卡点），再当评委（打分）
3. **不许给客气分**：提示词里写明"虚高的分数会让作者失去改进的机会"
4. **每轮换新读者**：不能复用

**达标条件**：总分 ≥48/60，且无单项 <7
