# 第十二章 先问一句，再看三拍

周五下午四点半，你从屏幕前抬起头，余光扫过墙上的考勤看板。九点五十八，十点零二，九点五十六，一排绿色的小圆点。没有人拍着桌子宣布过“你们必须准时”，但每个人都学会了。最早那个总迟到的同事，在第三次被私下约谈之后也乖了。现在哪怕闹钟坏了，他都会在九点五十惊醒。

上周五，一个新来的年轻人四点五十就收拾包准备走，整个办公室安静了一瞬。没人说他错了，主管甚至笑着说了句“早点回去好”。但那种安静你接住了。第二天他五点半才走。没有任何规则禁止四点五十离开，可一张看不见的图替所有人判定了：那个点走，是出格的。

你自己的身体里也跑着一张同样的图。某个健身 app 提醒你今天步数没达标，半夜你会因为“少走了两千步”隐隐不安；睡前瞄一眼睡眠分数，不到九十就有点焦虑。没人扣你工资，你自己当起了法官。控制一旦内化，就不需要外部监管者了，那张无人画的图，最后画进了你自己的脑子里。

这张图在书里有过名字：控制分布图。癌细胞、归零的库存、被营收压扁的工作室、被论文指标碾碎的实验室，前面十二章看过太多张这样的图，也看过它们怎么把一个个还站着的系统拖垮。这一章回答两个更实际的问题：动手改变一个系统之前，怎么提前看出代价？系统已经不对劲的时候，怎么找到真正的病灶？

## 动手之前，先问一句

第二章说过，控制从来就没有免费过。你在任何一个维度上按下随机性，它都会从别的维度鼓出来。这个道理听多了容易麻木，所以把它变成一个动作：每次伸手去拧什么之前，先停十秒，问一句——

熵会去哪个邻居家？那个邻居扛得住吗？

一家公司嫌会议太多，定了一条规矩：所有会议不得超过三十分钟。规矩本身没有错。但如果定之前有人问一句“熵会去哪”，答案不难猜：开不完的事会挪到会后，变成走廊里的小会对齐，变成邮件里越写越长的解释，变成两个部门各干各的、上线那天才发现撞车。邻居有三个：走廊里的小圈子、收件箱、上线事故。前两个多半扛得住，第三个未必。想清楚这一点，规矩照样定，但要给跨部门的活儿留一条不用开会的对齐通道。控制还是那条控制，搬出去的熵去了哪，却是挑过的。

反过来，没问这一句的代价，书里已经见过太多次。管价格，熵去了黑市；住院按病组打包付费，熵去了“查不出明确大病就不该占着床位”的老人身上；把库存压到零，熵蹲在每一次供应链打喷嚏的瞬间。做这些决定的人没有一个是坏人，他们只是动手之前，没有人停下来问那一句。

回到你的团队。假设明天要上一套考勤系统，把这句问出来：熵会去哪？顺着推：打卡收走的是时间上的弹性，弹性去的地方叫主动交流——帮隔壁组看个问题的十分钟，试一条没人验证过的路子的一上午。邻居还有谁？那些最安静、最不会抱怨的骨干。他们扛得住吗？表面上能扛很久，因为这类邻居从来不报警，它们只是慢慢变闷。问到这里你就会明白，考勤要配一条豁免，比如每周留一个不打卡的深度工作日，给交流维度的熵留个出口。规矩还是你的规矩，只是搬家之前，先看了一眼邻居的脸色。

当然，更多的时候，控制早就发生了，当年没人问过那一句。熵流了很多年，系统开始出现说不清的症状：还活着，报表还行，但哪里都不对劲。这时候，一句自检不够用了。

## 已经病了：先看停在第几拍

第七章说过，活的系统都在转同一个圈：碰撞逼出新编码，新老编码组合暴增，环境筛选把好的固化下来，然后进入下一轮。三拍都在转，系统就在长。系统出毛病，绝大多数时候是这个圈有一拍悄悄停了。诊断的任务，就是把停掉的那一拍找出来。

找之前，得先做一点笨功夫：把那张无人画的控制分布图摊开，顺着熵的流向走一遍。两步。第一步，盘点控制落在哪些维度上，明文的算，默契的也算——考勤、代码行数、客户响应时长，再加上那些没有名字的：“谁先离开会议室”“消息多久必须回”“请假用什么语气”。第二步，追问这些维度挤出来的熵流到了谁身上。承接熵的维度从来不报警，只默默记账：考勤压严之后，站会上话变少了，跨组的闲聊没了，故障修复越赶越糙。它们不喊疼，但代价是真的。

拿一支十人的技术小队走一遍。图摊开来，控制几乎全压在交付速度上，三条线拧得紧紧的，外加代码评审通过率和线上故障数两条。另一面，自主选题、跨岗轮换、失败复盘这几个维度几乎是空白。熵的流向也清楚：站会越来越短、越来越像走过场，是交流这根外机饱和了；修复越赶越糙，是质量这根外机快满了；长期规划没人做，等一次真正的范式切换，熵会直接流到生存维度。

图摊完了。现在对照三拍，看这个圈停在了哪里。

### 第一拍断了：碰撞消失

碰撞是循环的起点：系统跟现实撞上，撞出“现有编码处理不了”的东西，新编码才有机会出生。第一拍断了的系统，症状很一致：没人再提新想法，复盘走过场，错误发生了，却没变成任何人的经验。

第五章见过这种死法。一轮裁员之后，公司账面更好看了，流程照跑，但发动机凉透了。裁掉的不是一个个人头，是旧编码的载体——知道坑是怎么踩出来的那批人。事故、复盘、新经验、再碰撞，这个循环靠人来传。人走了，第一拍就断了，剩下的人进入纯执行模式。系统还在动，只是在等死，报表还没反映出来而已。

小一点的组织也一样。街角一家开了二十年的面馆，老厨师退休，老板从连锁品牌挖来年轻班子。菜单没变，味道没变，半年后你才咂摸出哪里不对：再也没有新菜冒出来了。老厨师在的时候，熟客随口一句“今天想吃口重的”，第二天锅里就多了一种做法。那些没写进菜单的手艺，全在他脑子里，跟每一张熟脸天天碰撞。新班子严格照标准出餐，出品稳定，稳定得像一台机器。机器不长新东西。

第一拍断了，修法只有一个：把碰撞请回来。留出失败的空间，让复盘重新长牙，让最靠近现场的人有资格当场改东西。注意，缺的不是“创新激励”，是碰撞的原材料——现实。

### 第二拍空了：组合枯萎

第二拍的毛病更隐蔽，因为它看起来还在出新东西。新品照发，版本照更，但所有新东西都长得像旧的：换配色、换文案、换包装，新老编码之间不再杂交。

第八章那只丑萌玩偶走到后期就是这样。人设编码立得住，上新节奏也没停，可新系列越来越像流水线换皮：框架不再跟外面的世界撞出真变异，组合暴增退化了排列组合。粉丝没有一夜变心，只是再也吃不到没吃过的新东西，吃不着吃不着，人就散了。

组织里有种更隐蔽的同类病：一家公司连续五年只招同一两所学校同一个专业的毕业生。每个人单看都优秀，团队的知识结构却一年比一年同质。开会永远能达成共识——这恰恰是危险信号。观点在里面撞不出火花，因为大家脑子里的初始编码库几乎一样。多样性不是场面话，它是组合暴增的原材料。

第二拍空了，修法是把异质性请回来：不同来历的人，不同渠道的信息，不同行业的打法。宁可短期吵得凶一点。

### 第三拍失灵：筛选被架空

第三拍断了最致命，因为它坏的不是“长不出新东西”，而是“坏东西死不掉”。筛选的本意，是让现实自动淘汰不适合的编码。筛选失灵的系统，错误可以一直活着，甚至活得很好。

苏联的计划机器是个极端样本。计划部门需要真实的产能信息，可层层上报的报表，每一层都有动机递上一个好看的数字。筛选机制还在转，但它筛的已经是“谁的报表编得好”，不再是“谁的工厂干得好”。几十年攒下的假数据，最后在切尔诺贝利一起炸了出来。

AI 行业近年有个流行的信念：数据够多、模型够大，智能就会自己涨上去。这个信念错把第三拍理解成了喂料。真正催生新编码的是跟物理世界的碰撞——撞墙、挨饿、犯错之后的痛感。喂料替代不了筛选：模型擅长组合已有的编码，可每一个真正的进步，仍要有人带着它一起撞向真实的世界。

小尺度上也有同样的病。一个产品团队把应用商店的差评折叠，把社群里的负面发言设为先审后发，季报上的满意度一路飘红。筛选机制没有消失，它被人自己拆了：现实的声音进不来，坏的做法就永远不会被淘汰。直到某天，卸载率替用户把话说完。

第三拍失灵，修法是把筛选交还给现实：让差评能被看见，让坏结果真能淘汰坏做法，让报表对得上车间。

### 三拍之外：门还开着吗

定位了断拍，最后还要压一道总的判准：这套控制体系，整体上是在给进化留空间，还是在把进化的门一扇扇关上？

判断的办法不抽象，看迹象。团队里，还有没有人敢提“也许我们方向错了”？还有没有不经安排的自发碰撞？一个异想天开的点子，是被接住了，还是立刻被“这不产生数字”驳回？身体里，你还会不会因为好奇去试一件没用的事？还留不留得住一段无所事事的空白？这些迹象在，门就开着；它们一个个消失，门就在一扇扇关上。门很少被一声巨响关死，它是一声一声“错”被弹回去，慢慢焊上的。

开门要付代价，这点得说清楚。给试错留余地，意味着接受一些实验会失败、一些时间会“浪费”；给寻熵留空隙，意味着接受一段不产生任何数字的空白。判准没让你把控制全撤掉，它让你看清楚的是：你收紧的那些线，有没有顺手把进化要用的门也带上了。门开着，哪怕此刻效率不高，系统还有翻盘的余地。门关了，报表再漂亮，系统也已经从活的变成死的，区别只是数字还没反映出来。

## 一张能带走的表

自检一句，断拍一望，判准一压，诊断就算做完了。为了让它能从书上走到你的纸上，把它落成一张表。先是那支十人小队画完的样子：

| 维度 | 压了什么 | 谁在接熵、还能扛多久 | 门开着吗 |
|------|----------|------------------------|----------|
| 交付速度 | 需求响应天数、发版节奏、故障修复时限，三条线拧到最紧 | 团队成员的自主时间 | 只朝一个方向开 |
| 代码质量 | 评审通过率、线上故障数压得很死 | 工程师的休息与耐心：修复越赶越糙，这根外机快满了 | 半开：标准还在，但没人敢报真问题 |
| 主动交流 | 无明文禁止，但“不算交付”的默契压着它 | 这根外机已经饱和：站会越开越短 | 正在一扇扇关上 |
| 自主选题、跨岗轮换、失败复盘 | 完全空白，默认“自然会好” | 还没有人接——它们是下一次冲击的爆点 | 关死了：碰撞和变异没有土壤 |

下面是空白模板，照着抄就能用：

| 维度 | 压了什么 | 谁在接熵、还能扛多久 | 门开着吗 |
|------|----------|------------------------|----------|
|      |          |                        |          |
|      |          |                        |          |
|      |          |                        |          |

用法三句话：左列写下你压得最紧的三到五个维度，别漏掉那些没写进制度、却人人都在遵守的；中列顺着每根线往下追，代价落在了谁头上，那个维度还剩几成余量；右列只填一个词，开着、半开，还是关了。填完之后再补一行注脚：这个圈停在第几拍——是没人提新想法了，是新东西全是换皮，还是坏做法死不掉了。停在哪一拍，修法就在哪一拍。

到这里，诊断的工具齐了。但你很快会撞上一个更麻烦的事实：很多系统并不是看不见病灶。学术圈不是没人知道造假，那家公司也不是没人觉得不对劲。它们是看见了，也治不了。为什么一个系统会眼睁睁看着自己烂掉？下一章，我们去见全书最深的那道坎。
