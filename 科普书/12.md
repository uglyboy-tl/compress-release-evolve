周五下午四点半，你从屏幕前抬起头，余光扫过墙上的考勤看板。九点五十八，十点零二，九点五十六，一排绿色的小圆点。没有人拍着桌子宣布过“你们必须准时”，但每个人都学会了。最早那个总迟到的同事，在第三次被私下约谈之后也乖了。现在哪怕闹钟坏了，他都会在九点五十惊醒。

上周五，一个新来的年轻人四点五十就收拾包准备走，整个办公室安静了一瞬。没人说他错了，主管甚至笑着说了句“早点回去好”。但那种安静你接住了。第二天他五点半才走。没有哪条规矩禁止四点五十离开，可一张看不见的图替所有人判定了：那个点走，是出格的。

你自己的身体里也跑着一张同样的图。某个健身 app 提醒你今天步数没达标，半夜你会因为“少走了两千步”隐隐不安；睡前瞄一眼睡眠分数，不到九十就有点焦虑。没人扣你工资，你自己当起了法官。控制一旦内化，就不需要外部监管者了，那张无人画的图，最后画进了你自己的脑子里。

这张图横着是维度，竖着写三件事：这一维被压了什么，熵落到了谁身上，门还开着吗。癌细胞、归零的库存、被营收压扁的工作室、被论文指标碾碎的实验室，前面几章看过太多张这样的图，也看过它们怎么把一个个还站着的系统拖垮。这一章回答两个更实际的问题：动手改变一个系统之前，怎么提前看出代价？系统已经不对劲的时候，怎么找到真正的病灶？

## 动手之前，先问一句

控制从来没有免费过。你在任何一个维度上按下随机性，它都会从别的维度鼓出来。这个道理听多了容易麻木，所以把它变成一个动作：每次伸手去拧什么之前，先停十秒，问一句——

熵会去哪个邻居家？那个邻居扛得住吗？

一家公司嫌会议太多，定了一条规矩：所有会议不得超过三十分钟。规矩本身没有错。但如果定之前有人问一句“熵会去哪”，答案不难猜：开不完的事会挪到会后，变成走廊里的小会对齐，变成邮件里越写越长的解释，变成两个部门各干各的、上线那天才发现撞车。邻居有三个：走廊里的小圈子、收件箱、上线事故。前两个多半扛得住，第三个未必。想清楚这一点，规矩照样定，但要给跨部门的活儿留一条不用开会的对齐通道。控制还是那条控制，搬出去的熵去了哪，却是挑过的。

反过来，没问这一句的代价，书里已经见过太多次。管价格，熵去了黑市；住院按病组打包付费，熵去了“查不出明确大病就不该占着床位”的老人身上；把库存压到零，熵蹲在每一次供应链打喷嚏的瞬间。做这些决定的人没有一个是坏人，他们只是动手之前，没有人停下来问那一句。

回到你的团队。假设明天要上一套考勤系统，把这句问出来：熵会去哪？顺着推：打卡收走的是时间上的弹性，弹性去的地方叫主动交流：帮隔壁组看个问题的十分钟，试一条没人验证过的路子的一上午。邻居还有谁？那些最安静、最不会抱怨的骨干。他们扛得住吗？表面上能扛很久，因为这类邻居不报警，它们只是慢慢变闷。问到这里你就会明白，考勤要配一条豁免，比如每周留一个不打卡的深度工作日，给交流维度的熵留个出口。规矩还是你的规矩，只是搬家之前，先看了一眼邻居的脸色。

当然，更多的时候，控制早就发生了，当年没人问过那一句。熵流了很多年，系统开始出现说不清的症状：还活着，报表还行，但哪里都不对劲。这时候，一句自检不够用了。

## 已经病了：先看断在哪一处

活的系统都在转那个圈：新编码被逼出来，新老编码组合暴增，好的被环境固化下来。三样都在转，系统就在长；出毛病，绝大多数时候是有一样悄悄停了。诊断的任务，就是把停的那一处找出来。

找之前先做一点笨功夫：把那张无人画的图摊开，顺着熵的流向走一遍。第一步，盘点控制落在哪些维度上，明文的算，默契的也算：考勤、代码行数、客户响应时长，再加上那些没有名字的：“谁先离开会议室”“消息多久必须回”“请假用什么语气”。第二步，追问这些维度挤出来的熵流到了谁身上。承接熵的维度不报警，只默默记账：考勤压严之后，站会上话变少了，跨组的闲聊没了，修复越赶越糙。

拿一支十人的技术小队走一遍。控制几乎全压在交付速度上，外加代码评审通过率和线上故障数；另一面，自主选题、跨岗轮换、失败复盘几乎是空白。熵的流向也清楚：站会越来越短、越来越像走过场，是交流这根口子饱和了；修复越赶越糙，是质量这根口子快满了；长期规划没人做，等一次真正的范式切换，熵会直接流到生存维度。

图摊完了，对照这三样看它断在哪里。断法的机制不再重讲，这里只做辨认，修法也在那一章。

### 碰撞断了：没人碰了

症状很一致：没人再提新想法，复盘走过场，错误发生了却不变成任何人的经验。那轮裁员是这样（把知道坑是怎么踩出来的人一起裁了），一支球队换掉整个教练组也是这样（打法还在，只是再没有新战术）。走掉的都不是人头，是旧编码的载体。修法只有一个：把碰撞请回来，留出失败的空间，让复盘重新长牙，让最靠近现场的人有资格当场改东西。缺的不是“创新激励”，是碰撞的原材料：现实。

### 组合枯了：出来的全是旧货

它更隐蔽，因为看起来还在出新东西：新品照发，版本照更，但每一样都长得像旧的。共情编码的第三种死法（内容不新）就是这样；组织里也有同类病：连续五年只招同一两所学校同一个专业的毕业生，开会永远能达成共识，而观点撞不出火花，恰恰因为大家脑子里的初始编码库几乎一样。

修法：把异质性请回来——不同来历的人，不同渠道的信息，不同行业的打法。宁可短期吵得凶一点。

### 筛选失灵：坏东西死不掉

它最致命，因为坏的不是“长不出新东西”，是坏东西死不掉。苏联那台计划机器是极端样本：层层上报的报表，每一层都有动机递个好看的数字，于是筛子筛的变成了“谁的报表编得好”。小尺度上更常见：把差评折叠、把负面发言先审后发，季报上的满意度一路飘红——直到卸载率替用户把话说完。

修法：把筛选交还给现实——让差评能被看见，让坏结果真能淘汰坏做法，让报表对得上车间。

### 这三样之外：门还开着吗

定位了断在哪一处，最后还要压一道总的判准：这套控制体系，整体上是在给进化留空间，还是在把进化的门一扇扇关上？

判断的办法不抽象，看迹象。团队里，还有没有人敢提“也许我们方向错了”？还有没有不经安排的自发碰撞？一个异想天开的点子，是被接住了，还是立刻被“这不产生数字”驳回？身体里，你还会不会因为好奇去试一件没用的事？还留不留得住一段无所事事的空白？这些迹象在，门就开着；它们一个个消失，门就在一扇扇关上。门很少被一声巨响关死，它是一声一声“错”被弹回去，慢慢焊上的。

开门要付代价。给试错留余地，意味着接受一些实验会失败、一些时间会“浪费”；给寻熵留空隙，意味着接受一段不产生任何数字的空白。判准没让你把控制全撤掉，它让你看清楚的是：你收紧的那些线，有没有顺手把进化要用的门也带上了。门开着，哪怕此刻效率不高，系统还有翻盘的余地。门关了，报表再漂亮，系统也已经从活的变成死的，区别只是数字还没反映出来。

## 拿一个还活着的试试

上面诊断的，都是已经塌了的，或者假设的。这套东西到底能不能事先用？那就找一件此刻还站着、而且你还天天看得见的事来试，比如大学。

按两条通道看。第一列（钱、楼、设备、编制）它过得不差：学费、拨款、项目经费，总量在过去几十年里一直在往上走；它也不缺产能，论文和毕业生的产量一直在涨。

要害在第二列。大学真正在干的事，是让一群人凑在一起，把还没想明白的东西往彼此桌上推：课堂上的一句追问，导师办公室里一次跑题的争论，两个不同系的人中午碰上的十分钟。这条通道不花钱，可它有自己的瓶颈：它得靠人跟人真的撞上，而每一次撞上都要花掉一个人一下午。被挤掉的是哪一部分？正是那些不算成果的时间：课时要够、论文要够、项目要够，每一样都能记账，唯独那十分钟记不进任何一格。于是它被挪到了会议之外、下班之后，或者干脆没有了。

对照这三样走一遍：筛选最危险，而且已经在失灵了。论文数、帽子、经费都是能量出来的东西，于是筛子慢慢从“谁的东西经得起时间”变成“谁的报表编得漂亮”，和苏联那台计划机器是同一种病，只是它还体面着。碰撞和组合暂时还没断：人还在，碰撞也还在发生，只是越来越靠少数人自愿加班撑着。

大学的第一列确实也在出问题：学生变少、经费变紧，这两件事眼下就摆在眼前。我要说的是另一件：第二列退得比第一列快，快在那几个数得出来的地方。

哪里数得出来？不用等出事，今天就能看：跨系合作的项目是不是一年比一年少；年轻老师互读对方东西的次数；“这段路不划算”这句话，还有没有人敢说出口。三个数里有一个当家的：跨系合作的项目数。它躺在科研处的台账里，谁都能去查；另外两个只能靠身在其中的人体感，外人问不出来。

我把话押在这个上：如果大学先撑不住，先垮的是这几个数，不是账。不过两条线的时间刻度不一样：生源和经费的变化，两三年就能看出来；我这条账要等五到十年。所以先到的是快的那条：如果三年之内先听见某类学校成批停招、成批关门，那我还没来得及结账就先输了。

所以两条都写下来。

一种：如果未来五到十年里，这几个数没有继续降，甚至回升了（比如跨系合作变多、年轻老师又开始互相当第一读者了），那说明第二列比我估的结实，我错了。

另一种：如果大学先因为钱或生源出事（某个专业成批停招、某类学校成批关门），那说明第一列才是它的命门，我也错了。

（还有一种结局不在这两条里：什么也没发生。数照样慢慢降，人照样慢慢走，十年过去看不出哪天是拐点。这种情况不叫“我说对了”，叫这台机器坏得很慢，慢到没人需要为它做个决定。）

你也可以拿自己的地方试一遍。写下你待的那个系统（一家公司、一个班、一个群都行），先写一句“它会先在哪一列断”，再写下“什么情况算我猜错了”。写不出后一句，说明你只是在感觉，不是在判断。

## 一张能带走的表

自检一句，看断一望，判准一压，诊断就算做完了。为了让它能从书上走到你的纸上，把它落成一张表。先是那支十人小队画完的样子：

| 维度 | 压了什么 | 谁在接熵、还能扛多久 | 门开着吗 |
|------|----------|------------------------|----------|
| 交付速度 | 需求响应天数、发版节奏、故障修复时限，三条线拧到最紧 | 团队成员的自主时间 | 只朝一个方向开 |
| 代码质量 | 评审通过率、线上故障数压得很死 | 工程师的休息与耐心：修复越赶越糙，这根口子快满了 | 半开：标准还在，但没人敢报真问题 |
| 主动交流 | 无明文禁止，但“不算交付”的默契压着它 | 这根口子已经饱和：站会越开越短 | 正在一扇扇关上 |
| 自主选题、跨岗轮换、失败复盘 | 完全空白，默认“自然会好” | 还没有人接，它们是下一次冲击的爆点 | 关死了：碰撞和变异没有土壤 |

下面是空白模板，照着抄就能用：

| 维度 | 压了什么 | 谁在接熵、还能扛多久 | 门开着吗 |
|------|----------|------------------------|----------|
|      |          |                        |          |
|      |          |                        |          |
|      |          |                        |          |

用法三句话：左列写下你压得最紧的三到五个维度，别漏掉那些没写进制度、却人人都在遵守的；中列顺着每根线往下追，代价落在了谁头上，那个维度还剩几成余量；右列只填一个词，开着、半开，还是关了。填完之后再补一行注脚：这个圈断在哪一处，是没人提新想法了，是新东西全是换皮，还是坏做法死不掉了。断在哪一处，修法就在哪一处。

到这里，诊断的工具齐了。
