# 写作实操清单

这不是填空题。它是一份写文章时对照用的清单——从热点事件到一篇有节奏的叙事。

## 核心方法

两阶段：**诊断用熵，治疗用编码。**

诊断三步走：**先问一句，再看三拍，最后压判准。**

- **先问一句**：事件里动手的人，在按下控制之前，问过那句"熵会去哪个邻居家"吗？没问的，代价迟早冒出来——那笔熵去了哪，哪个邻居先扛不住。
- **再看三拍**：编码进化循环停在哪一拍——碰撞（第一拍）、组合（第二拍）、筛选（第三拍）。停在哪拍，修哪拍。
- **压判准**：这套控制整体上是在给进化留空间，还是在把进化的门一扇扇关上？

不用预设答案——有些事件的核心是"不该控的维度被控死了"，有些是"该控的没控住"，有些是散热带宽出了问题。顺着事件本身的逻辑走，别把事件往框架里塞。

## 诊断阶段（用熵）

### 1. 收集素材

搜索新闻、采访、评论，找到关键人物和细节。记录那些让你觉得"不对劲"的地方。不要急着套概念。

### 2. 先问一句：动手之前，问过那句话吗？

控制从来就没有免费过。在任何一个维度按下随机性，它都会从别的维度鼓出来。所以每次伸手去拧什么之前，该停十秒问一句：**熵会去哪个邻居家？那个邻居扛得住吗？**

把这句话用到事件上，检验事件里的决策者：

- 如果没问过——追问那笔熵去了哪，哪个邻居先扛不住，最后怎么爆的。这通常是文章"代价"一段的骨架。
- 如果问过但没扛住——那是散热带宽的第二层天花板，不是没想过，是没地方放。

例子：会议限时三十分钟，开不完的事挪到会后走廊、邮件、上线事故；管价格，熵去黑市；压库存，熵蹲在供应链打喷嚏的瞬间；住院按病组打包付费，熵落到"查不出大病就不该占床"的老人身上。

这一步的产出：**熵流向图**——控制压在哪，涌向哪个邻居，哪个先报警（或从不报警、只默默记账）。

### 3. 两步侦察：把控制分布图摊开

控制早已发生、症状不明的系统，先做两步笨功夫：

- **控制盘点**：控制落在哪些维度上？明文的算，默契的也算——考勤、代码行数、客户响应时长，还有那些没有名字的："谁先离开会议室""消息多久必须回"。
- **熵流追踪**：这些维度挤出来的熵流到了谁身上？承接熵的维度从来不报警，只默默记账。追出每个受压维度的接熵邻居，标出哪根外机快满了。

写文章时，这一步就是"代价"一段的素材总库。

### 4. 再看三拍：循环停在哪一拍

活的系统都在转同一个圈：碰撞逼出新编码 → 新老编码组合暴增 → 环境筛选固化。三拍都在转，系统就在长。系统出毛病，绝大多数时候是有一拍悄悄停了。诊断的任务，就是把停掉的那一拍找出来。

- **第一拍断了：碰撞消失。** 症状：没人再提新想法，复盘走过场，错误发生了却没变成任何人的经验。裁员裁掉旧编码的载体——知道坑是怎么踩出来的那批人走了，剩下的人进入纯执行模式；老面馆老厨师退休，新班子出品稳定得像台机器，机器不长新东西。
  → **修法：把碰撞请回来。** 留出失败空间，让复盘重新长牙，让最靠近现场的人有资格当场改东西。缺的不是"创新激励"，是碰撞的原材料——现实。
- **第二拍空了：组合枯萎。** 症状：新品照发，版本照更，但所有新东西都长得像旧的——换配色、换文案、换包装，新老编码不再杂交。丑萌玩偶后期新系列流水线换皮；公司连续五年只招同一学校同专业，开会永远能达成共识——这恰恰是危险信号。
  → **修法：把异质性请回来。** 不同来历的人、不同渠道的信息、不同行业的打法。宁可短期吵得凶一点。
- **第三拍失灵：筛选被架空。** 症状：坏东西死不掉。筛选还在转，但筛的已经不是"谁的工厂干得好"，而是"谁的报表编得好"。苏联层层上报假数据，最后在切尔诺贝利一起炸出来；Scaling Law 把第三拍理解成喂料；团队把差评折叠、负面发言先审后发，季报满意度一路飘红。
  → **修法：把筛选交还给现实。** 让差评能被看见，让坏结果真能淘汰坏做法，让报表对得上车间。

这一步的产出：**断拍定位**——停在第几拍，对应哪条修法。

### 5. 压一道判准：门还开着吗

定位了断拍，再压一道总的判准：这套控制体系，整体上是在**给进化留空间，还是在把进化的门一扇扇关上**？

判断的办法不抽象，看迹象：还有没有人敢提"也许我们方向错了"？还有没有不经安排的自发碰撞？一个异想天开的点子，是被接住了，还是立刻被"这不产生数字"驳回？门很少被一声巨响关死，它是一声一声"错"被弹回去，慢慢焊上的。

判准不问效率高不高，它问系统还是不是活的。门关了，报表再漂亮，系统也已经从活的变成死的，区别只是数字还没反映出来。

### 6. 深化工具一：为什么治不好（自指闭环）

有些系统不是看不见病灶，是看见了也治不了。诊断完断拍，再补三道检查：

- **纠偏在框内还是框外？** 系统对问题的每一次反应，是换人、加指标、开整顿会（框内），还是真的指向编码本身（框外）？
- **谁定义问题，谁提供方案？** 制造问题的编码，是不是同时垄断着解决方案？
- **求知型还是护利型？** 求知型闭环能被够硬的外部事实撞开一道缝（学术造假里核心编码还写着"求真"）；护利型闭环把每次冲击消化成燃料（换 CEO 不动编码，只换一张面对公众的脸）。

闭环的两个前兆：**编码反转**（手段变成目的，读数指挥发动机，危机变人事变动）、**维度压缩偏误**（只度量可度量的，不可度量就没有合法性）。

对写文章的用处：如果事件是自指闭环，"盲区"和"困境"两段就有了骨架——从内部看每一步都在积极应对，从外面看在无限缩小的圆圈里打转。

### 7. 深化工具二：编码链四步

事件呈现多层嵌套（如资本市场→管理层→员工）时，在断拍定位之上加这四步：

- **拆层级**：涉及哪几层，每层的主导编码是什么？
- **找根编码**：顺着编码链往上，驱动下层的源头在哪一层？（它不受更高层直接惩罚）
- **追熵泄漏**：沿着编码链从上往下问——每个维度的压缩把熵挤到了哪？最终是耗散还是堆积？
- **定杠杆层**：哪层的编码改变不会受更高层惩罚？那里才是破局点。

### 8. 高频模式速查（遇上了再用，别硬套）

诊断走完还模糊时，用这些特征对号入座，反推是哪一拍的问题：

- **编码反转**：衡量工具被当成目的本身（论文数量、KPI、增长速度）
- **维度压缩偏误**：可度量维度被天然放大，不可度量但对生存至关重要的维度被系统性忽视
- **散热通道堵塞**：释放熵的维度被一步步收窄，熵在内部堆积
- **弹性项刚性化**：本应是系统健康输出的指标（增长率、利润率）变成必须遵守的输入约束
- **控制耦合**：上层路由和下层内部控制作用在同一维度上互相拉扯
- **路由失效/绕行**：母系统该管不管、不该管硬管，子系统自己找新的熵流出路

### 9. 诊断落成一张表

把上面的产出落成一张能带走的表（写文章时，这张表就是素材总目录）：

| 维度 | 压了什么 | 谁在接熵、还能扛多久 | 门开着吗 |
|------|----------|------------------------|----------|
|      |          |                        |          |

用法三句话：左列写压得最紧的三到五个维度，别漏掉那些没写进制度、却人人都在遵守的；中列顺着每根线往下追，代价落在谁头上，那个维度还剩几成余量；右列只填一个词——开着、半开、还是关了。

填完补一行注脚：这个圈停在第几拍？是没人提新想法了，是新东西全是换皮，还是坏做法死不掉了。**停在哪一拍，修法就在哪一拍。**

## 治疗阶段（用编码）

不是"解决问题"，是**找到能让系统重启编码进化循环的杠杆**。

### 对应断拍的修法

断在哪一拍，就从哪一拍让循环重新转起来：

- **第一拍断了**：把碰撞请回来——让最靠近现场的人有资格当场改东西，让复盘重新长牙，让错误重新变成经验。
- **第二拍空了**：把异质性请回来——不同来历的人、不同渠道的信息、不同行业的打法，宁可短期吵得凶一点。
- **第三拍失灵**：把筛选交还给现实——让坏结果真能淘汰坏做法，让报表对得上车间。

注意：这些修法都不是"加一层新压缩映射"。给试错留余地，意味着接受一些实验会失败；给寻熵留空隙，意味着接受一段不产生数字的空白。这是开门的代价。

### 遇到自指闭环：先看见圈

自指闭环里，修法不在断拍里。第一步永远是看见这个圈——知道自己被困住了，知道眼前所有选项都是这套编码生成的。靠的不是更努力（越多越紧），不是换人（环里的标准动作），不是加指标（给圈再加一层砖）。

打破闭环的现成手艺：

- **第一性原理**：站到盒子外面。剥掉所有历史包袱和约定俗成的前提，问"这个系统作为一个整体，输入输出之间最基本的关系是什么"。它给的不是一个答案，是一个站位——从框架外面往里扔事实。
- **PDCA**：亲手转那台发动机。计划（选一个离不稳定边界远、还有余量的维度）、执行（施加一次压缩）、检查（熵漏没漏到不该漏的邻居）、固化（没漏就定下来，漏了就退回来）。它不绑定任何指标，所以不容易踩编码反转的坑。
- **守住图的宽度（中庸）**：拒绝把任何一条轴拧到头。耕读传家、常平仓——不把鸡蛋放一个维度的文化本能。

### 杠杆自检：再问一次"先问一句"

方案提出来之后，用"先问一句"自检：**我的杠杆会把熵挤到哪个新邻居？那个邻居扛得住吗？**

如果我的方案只是换一个刻度盘——用 X 指标取代 Y 指标，用更细的论文指标修论文造假——那它本身就是一次新的压缩映射。它不会重启进化循环，只是换了个地方压缩。

真正的杠杆是**调整奖惩结构**：让短视行为不再免费，让长期积累被看见，让熵泄漏的成本由释放者承担。出路必须是能自我维持的进化机制，不是一次性修补。

## 叙事结构

### 推荐七段（不是每篇都要走完，用不上的跳过）

1. **开头**：用一个具体的人或事件切入
2. **问题**：揭示被颠倒的目的——哪个维度被压死了，谁在只看那个数字
3. **代价**：追踪熵的流向——被挤走的熵去了哪个邻居家，哪个先扛不住
4. **盲区**：为什么看不见错——纠偏如何在框架内打转（编码反转、维度压缩偏误）
5. **困境**：为什么看见了也改不动——自指闭环，围绕编码的依赖已经长成
6. **出路**：断拍对应的修法 + 站到框架外的手艺
7. **结尾**：回到具体的人

### 追问链

章节排列遵循**读者心里自然冒出的下一个问题**。每章结尾的结论制造疑问，下一章开头直接回应。

不要写"让我们看看另一个角度""但最容易搞反的还不是这个"这类桥句。

35 岁文章的自然链：留下的人怎么了 -> 为什么会这样（发动机停了） -> 公司做了什么（输血） -> 为什么管理层这样做（三个月牢笼） -> 这件事为什么重要（溢出） -> 那怎么办。

### 不做什么

- 不要先列概念再填例子
- 不要用"维度诊断""熵泄漏路径"这种咨询报告语言
- 不要用"此外""然而""值得注意的是"
- 不要用"不仅……而且……"
- 不要把"出路"写成建议清单——它应该是一个编码进化的框架

### 做什么

- 先讲故事，再引概念
- 混合长短句
- 直接陈述事实，信任读者
- 概念为叙事服务，不是反过来

## 风格优化

目标：兰小欢《置身事内》——**平实、理解而非指责、用叙事替代判断**。

### 特征对照

| 特征 | 说明 | 反面 |
|------|------|------|
| 理解结构，不指责个人 | 解释"为什么会这样"，不骂"谁做错了" | "从业者的傲慢""天真的傲慢" |
| 从具体案例切入 | 先讲一个故事、一个数据、一个人，再展开分析 | 直接抛出理论概念 |
| 口语化但不轻浮 | "冒出来了""水到渠成的事" | 论文腔（"从……的角度看……"）、滥用感叹号 |
| 短段落、短句 | 每段 2-4 句，手机屏幕一眼扫完 | 大段文字挤在一起 |
| 金句独立呈现 | 核心观点用引用块或加粗拎出来 | 埋在一大段话里被淹没 |
| 开放式结尾 | 收在问题或展望上，不强行给标准答案 | "综上所述"式的总结 |

### 流程

1. **通读，判断改动幅度**：已有叙事底子就微调，偏学术或偏指责则逐段重写语调
2. **标题优化**：公众号标题需要热词钩子——前半句设问（保留热词），后半句聊天式邀请；章节标题用问句代替陈述，去掉冒号结构
3. **逐段打磨**：
   - 去掉道德判断和指责语气："语重心长地告诉你"→"告诉你"。原则：描述行为，不给人贴标签
   - 打散长段落：超过 5 句的段落拆开。论点独立成段、金句独立成行、举例与结论分开
   - 加粗克制：每节最多 1-2 处，全文 5-8 处。只加粗开篇悬念、核心论断、核心隐喻、过渡设问、结尾收束
   - 引用块全文 1-2 处，只包装最生动的类比和意外感强的转折；三枚举并列时改列表
4. **检查完整性**：核心论点无遗漏、逻辑通畅、风格前后一致（不要前半段《置身事内》、后半段论文腔）

### 实际案例对照

| 问题 | 优化前 | 优化后 |
|------|--------|--------|
| 全篇指责他人 | "从业者的傲慢""天真的傲慢" | "当信仰替代了问题" |
| 开头太急 | 直接切入理论 | 增加过渡："要回答这个问题，我们得先聊聊……" |
| 语气过重 | "典型的废话文学新版本" | 引用块"这就像说'跑得快的人跑得快'" |
| 标题太正式的冒号结构 | "从 LLM 到 Agent：一个自然的延伸" | "不只是说，还要去做" |
| 带评价的修饰 | "人总是有一种本能，可以将最赤裸的选择包装成不得已的苦衷" | "包装成不同的名字并不奇怪" |
| 感叹号式指责 | "你大概会愤慨：看！" | "读到这儿，你大概会觉得愤慨——" |

### 注意

- **先读，再改**：先理解论证结构和核心观点，确保优化后不丢东西
- **尊重原文骨架**：不改结构、不改论点、不改论证顺序，只动语言、节奏、视觉呈现
- **保留原作者的独特表达**：好的类比、独特的叙事节奏不要为统一风格而抹掉——目标是让好内容更容易被读懂，不是套同一个模子

## 检查清单

### 分析层面

- [ ] 熵流向图推演过：控制压在哪，熵涌向哪个邻居，哪个先扛不住
- [ ] 断拍定位过：三拍（碰撞→组合→筛选）停在哪一拍，有对应修法
- [ ] 判准压过：这套控制是在给进化留空间，还是在把门一扇扇关上
- [ ] 检查过自指闭环：纠偏在框内还是框外；求知型还是护利型
- [ ] 出路是编码进化框架，不是换一个刻度盘；用"先问一句"自检过杠杆

### 叙事层面

- [ ] 先讲故事，再用系统概念加深
- [ ] 衔接靠逻辑追问链，不是靠桥句
- [ ] 概念为叙事服务，不是堆砌
- [ ] 无填充短语、否定式排比、三段式法则
- [ ] 粗体和破折号克制使用
- [ ] 删掉所有系统理论术语后文章还能站住

### 风格层面

- [ ] 理解结构，不指责个人
- [ ] 从具体案例切入，不抛理论概念
- [ ] 口语化，无论文腔和滥用感叹号
- [ ] 段落够短（2-4 句），适合手机阅读
- [ ] 结尾开放（问句或展望），非"综上所述"
