# 写作实操清单

这不是填空题。它是一份写文章时对照用的清单——从热点事件到一篇有节奏的叙事。

## 核心方法

两阶段：**诊断用熵，治疗用编码。**

诊断的总入口是三个问题：什么被压缩了？熵去了哪里？进化卡在哪一环？具体见下。不用预设答案——有些事件的核心是“不该控的维度被控死了”，有些是“该控的没控住”，有些是散热带宽出了问题。顺着事件本身的逻辑走，别把事件往框架里塞。

---

## 诊断阶段

### 1. 收集素材

搜索新闻、采访、评论，找到关键人物和细节。记录那些让你觉得“不对劲”的地方。不要急着套概念。

### 2. 用三问拆解事件

- **什么被压缩了？** 哪个维度被压成了单一指标？谁在只看这个数字？
- **熵去了哪里？** 熵不会消失。沿着压缩点追——被挤走的成本、风险、随机性落到了哪些不被度量的维度上？
- **进化卡在哪一环？** 三拍体检：碰撞产生新规则 → 新旧组合暴增 → 环境筛选固化。断在哪一拍？（35 岁裁员断在第一拍，拉布布松在第二拍，“递归自我改进”错在第三拍。）

### 3. 高频模式速查（遇上了再用，别硬套）

- **编码反转**：衡量工具被当成目的本身（论文数量、KPI、增长速度）
- **自指闭环**：纠偏动作全在编码框架内打转——看不见错；围绕编码长出的深度依赖，又让系统看见了也改不动
- **维度压缩偏误**：可度量的维度被天然放大，不可度量但对生存至关重要的维度被系统性忽视
- **散热通道堵塞**：释放熵的维度被一步步收窄，熵在内部堆积（睡眠篇）
- **弹性项刚性化**：本应是系统健康运行输出的指标（增长率、利润率），变成了系统必须遵守的输入约束
- **控制耦合**：上层路由和下层内部控制作用在同一维度上，互相拉扯
- **路由失效/绕行**：母系统该管不管、不该管硬管，子系统自己找新的熵流出路

### 4. 嵌套锁死情形的深化工具：编码链四步

如果事件呈现多层嵌套（如资本市场→管理层→员工），在三问之上加这四步：

- **拆层级**：这件事涉及哪几层，每层的主导编码是什么？
- **找根编码**：顺着编码链往上，驱动下层的源头在哪一层？（它不受更高层直接惩罚）
- **追熵泄漏**：沿着编码链从上往下问——每个维度的压缩把熵挤到了哪？最终是耗散还是堆积？
- **定杠杆层**：哪层的编码改变不会受更高层惩罚？那里才是破局点。

### 治疗方向

不是“解决问题”，是**找到能让系统重启编码进化循环的杠杆**。

- 进化循环断在哪一环？碰撞被压制、组合被锁死，还是新编码没有形成的通道？
- 新编码应容纳什么——用更宽的框架替代更窄的？
- 杠杆不能是加一层新压缩映射，而是**调整奖惩结构**——让短视行为不再免费，让长期积累被看见。
- 出路必须是能自我维持的进化机制，不是一次性修补。

## 叙事结构

### 推荐七段（不是每篇都要走完，用不上的跳过）

1. **开头**：用一个具体的人或事件切入
2. **问题**：揭示被颠倒的目的（什么被压缩了）
3. **代价**：追踪熵的流向路径
4. **盲区**：为什么看不见错——纠偏如何在框架内打转
5. **困境**：为什么看见了也改不动——围绕编码的依赖已经长成
6. **出路**：杠杆和编码进化方向
7. **结尾**：回到具体的人

### 追问链

章节排列遵循**读者心里自然冒出的下一个问题**。每章结尾的结论制造疑问，下一章开头直接回应。

不要写“让我们看看另一个角度”“但最容易搞反的还不是这个”这类桥句。

35 岁文章的自然链：留下的人怎么了 -> 为什么会这样（发动机停了） -> 公司做了什么（输血） -> 为什么管理层这样做（三个月牢笼） -> 这件事为什么重要（溢出） -> 那怎么办。

### 不做什么

- 不要先列概念再填例子
- 不要用“维度诊断”“熵泄漏路径”这种咨询报告语言
- 不要用“此外”“然而”“值得注意的是”
- 不要用“不仅……而且……”
- 不要把“出路”写成建议清单——它应该是一个编码进化的框架

### 做什么

- 先讲故事，再引概念
- 混合长短句
- 直接陈述事实，信任读者
- 概念为叙事服务，不是反过来

## 风格优化

目标：兰小欢《置身事内》——**平实、理解而非指责、用叙事替代判断**。

### 特征对照

| 特征 | 说明 | 反面 |
|------|------|------|
| 理解结构，不指责个人 | 解释“为什么会这样”，不骂“谁做错了” | “从业者的傲慢”“天真的傲慢” |
| 从具体案例切入 | 先讲一个故事、一个数据、一个人，再展开分析 | 直接抛出理论概念 |
| 口语化但不轻浮 | “冒出来了”“水到渠成的事” | 论文腔（“从……的角度看……”）、滥用感叹号 |
| 短段落、短句 | 每段 2-4 句，手机屏幕一眼扫完 | 大段文字挤在一起 |
| 金句独立呈现 | 核心观点用引用块或加粗拎出来 | 埋在一大段话里被淹没 |
| 开放式结尾 | 收在问题或展望上，不强行给标准答案 | “综上所述”式的总结 |

### 流程

1. **通读，判断改动幅度**：已有叙事底子就微调，偏学术或偏指责则逐段重写语调
2. **标题优化**：公众号标题需要热词钩子——前半句设问（保留热词），后半句聊天式邀请；章节标题用问句代替陈述，去掉冒号结构
3. **逐段打磨**：
   - 去掉道德判断和指责语气：“语重心长地告诉你”→“告诉你”。原则：描述行为，不给人贴标签
   - 打散长段落：超过 5 句的段落拆开。论点独立成段、金句独立成行、举例与结论分开
   - 加粗克制：每节最多 1-2 处，全文 5-8 处。只加粗开篇悬念、核心论断、核心隐喻、过渡设问、结尾收束
   - 引用块全文 1-2 处，只包装最生动的类比和意外感强的转折；三枚举并列时改列表
4. **检查完整性**：核心论点无遗漏、逻辑通畅、风格前后一致（不要前半段《置身事内》、后半段论文腔）

### 实际案例对照

| 问题 | 优化前 | 优化后 |
|------|--------|--------|
| 全篇指责他人 | “从业者的傲慢”“天真的傲慢” | “当信仰替代了问题” |
| 开头太急 | 直接切入理论 | 增加过渡：“要回答这个问题，我们得先聊聊……” |
| 语气过重 | “典型的废话文学新版本” | 引用块“这就像说‘跑得快的人跑得快’” |
| 标题太正式的冒号结构 | “从 LLM 到 Agent：一个自然的延伸” | “不只是说，还要去做” |
| 带评价的修饰 | “人总是有一种本能，可以将最赤裸的选择包装成不得已的苦衷” | “包装成不同的名字并不奇怪” |
| 感叹号式指责 | “你大概会愤慨：看！” | “读到这儿，你大概会觉得愤慨——” |

### 注意

- **先读，再改**：先理解论证结构和核心观点，确保优化后不丢东西
- **尊重原文骨架**：不改结构、不改论点、不改论证顺序，只动语言、节奏、视觉呈现
- **保留原作者的独特表达**：好的类比、独特的叙事节奏不要为统一风格而抹掉——目标是让好内容更容易被读懂，不是套同一个模子

## 检查清单

### 分析层面

- [ ] 三问覆盖完整：什么被压缩了、熵去了哪里、进化卡在哪一环
- [ ] 出路是编码进化框架（奖惩结构调整 + 新编码容纳方向），能自我维持，不只是一条建议

### 叙事层面

- [ ] 先讲故事，再用系统概念加深
- [ ] 衔接靠逻辑追问链，不是靠桥句
- [ ] 概念为叙事服务，不是堆砌
- [ ] 无填充短语、否定式排比、三段式法则
- [ ] 粗体和破折号克制使用
- [ ] 删掉所有系统理论术语后文章还能站住

### 风格层面

- [ ] 理解结构，不指责个人
- [ ] 从具体案例切入，不抛理论概念
- [ ] 口语化，无论文腔和滥用感叹号
- [ ] 段落够短（2-4 句），适合手机阅读
- [ ] 结尾开放（问句或展望），非“综上所述”
